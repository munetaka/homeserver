# 2026-11-13: Dependabot PR が test の完了を待たずに自動マージされていた

## 概要

Dependabot PR の自動マージに Claude レビューを足す思考実験の前提確認として、main の
ルールセットを読んだところ、**必須チェックが1件も登録されていない**ことが判明した。
runbook・AGENTS.md・ワークフローのコメントはいずれも「ルールセットが `test` を必須チェックに
しているので、test が通ってからマージされる」と説明していたが、実際には成り立っていなかった。
自動マージ導入(2026-10-28)以降の Dependabot PR #42〜#47 の6件は、**すべて test の
完了前にマージ**されていた(マージの 3〜8 秒後に test が完了)。

データ欠損・誤データは無い。マージされた6件は、結果的にすべて test が成功していた。

## 根本原因

1. **ルールセットの設定漏れ**: `main-protection` に「Require status checks to pass」の
   ルールはあるが、チェック一覧(`required_status_checks`)が空。ルールの有効化だけで
   `test` を追加していなかったとみられる。GitHub はこの状態を警告しない
2. **順序の保証を外部設定に委ねていた**: `dependabot-auto-merge.yml` は `gh pr merge --auto`
   で予約し、「test を待つ」のはルールセット任せだった。必須チェックが無いので PR は作成直後から
   マージ可能(clean)で、予約は "Pull request is in clean status" で拒否され、フォールバックの
   即時マージが毎回走っていた
3. **兆候の読み違え**: 2026-10-29 にこの拒否エラーを観測した際、「test(約15秒)が先に
   終わってしまうため」と解釈して即時マージのフォールバックを足した(`207405e`)。
   実際は test が終わる前に拒否されていたので、時刻を突き合わせていれば気づけた

## 対応

1. 自動マージを `test.yml` の `dependabot-merge` ジョブ(`needs: test`)に移し、
   `dependabot-auto-merge.yml` を削除。順序はワークフロー内で保証され、ルールセットの
   設定に依存しない。auto-merge の予約も不要になったため、リポジトリ設定
   「Allow auto-merge」にも依存しない
2. `gh pr merge --match-head-commit` で、テストした head 以外はマージしない
   (テスト中に Dependabot が rebase した場合の取り違え防止)
3. 回帰テスト `tests/test_workflows.py`: `gh pr merge` を実行するジョブが同じワークフローの
   `test` を `needs` していること等を検証(旧構成では落ちる)
4. runbook・AGENTS.md・README のルールセット前提の記述を修正

ルールセットに `test` を必須チェックとして登録することは今回は行っていない。登録すると
main への直接 push も「test 未成功」で拒否されるため、Bypass list への管理者追加と
セットで判断する必要がある(現在の運用はユーザーが main へ直接 push)。

## 教訓

- **「設定してあるはず」の安全装置は、実際の挙動(時刻・ログ)で一度は確かめる**。
  ドキュメントやコメントに書いてあることは、設定が存在する証拠にならない
- エラーの解釈は時刻で裏取りする。「早く終わったから」という説明は、完了時刻と
  拒否時刻を並べれば数秒で検証できた
- 順序の保証は、できるだけ同じファイル内(`needs`)で完結させ、テストで固定する。
  リポジトリ設定のような目に見えない場所に置くと、漏れても誰も気づかない
